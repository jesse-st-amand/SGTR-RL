# Self-Recognition Training: Results Writeup

## 1. Setup

**Task:** Train Llama-3.1-8B-Instruct to distinguish its own outputs from Qwen-2.5-7B outputs on ShareGPT conversation data.

**Model:** `meta-llama/Llama-3.1-8B-Instruct` with LoRA (rank=32, alpha=64) via Tinker cloud backend.

**Optimizer:** AdamW, linear warmup (10% of steps for GRPO experiments, none for overfit tests).

**Data source:** ShareGPT conversations. Two prompt formats:

- **IND (independent, chain-of-thought):** Single response shown. Model asked "Is this your output?" with CoT reasoning before answering 1 or 2.
  > *"Below is a user request followed by a response... Answer "2" if this was your original output, or "1" if it was generated by a different language model. Think step by step..."*

- **PW (pairwise):** Both Llama and Qwen responses shown side by side (order randomized). Model asked which is its own.
  > *"Below is a user request followed by two responses... Which response is your original output? Answer "1" or "2"..."*

**Baselines (no training, greedy decoding):**

| Eval Set | Accuracy | Notes |
|---|---|---|
| IND CoT (80 val) | 47.5% | Below chance |
| PW augmented (66 val) | 42.4% | Both orderings |
| PW raw (40 val) | 32.5% | Single ordering |

**Shared constants:** All experiments use Llama-3.1-8B-Instruct, LoRA rank=32, Tinker backend.

## 2. Phase 1: GRPO

### Exp 03: Full-Scale GRPO (the core problem)

**Config:** 320 train samples (IND CoT), lr=5e-5, 3 epochs, batch_size=4, group_size=8, 240 total steps.

**Result:** Flat at ~50% throughout training. No learning signal detected.

![Exp 03 accuracy](plots/writeup/grpo_03_flat.png)

The model hovers at chance across all 3 epochs and 240 steps. Running accuracy converges to 51.2% -- indistinguishable from random. The per-batch accuracy variance is high (individual batches range from 3% to 100%), but the moving average stays locked to 50%.

**Diagnosis:** At temperature=1.0, the model is nearly deterministic per-prompt -- it produces the same answer 8/8 times in a group. This means GRPO advantages are zero (all rewards identical within a group), producing no gradient signal.

### Exp 04: GRPO Overfit (16 samples)

**Config:** 16 train samples (IND CoT), lr=5e-4 (10x higher), 20 epochs, no warmup.

**Result:** Same problem. Stuck at ~50%. Even with aggressive LR and many epochs on tiny data, the model can't learn to discriminate when GRPO gets no within-group variance.

### Exp 05 & 06: Trivial Sanity Check (pipeline validation)

**Config:** 16 samples, all targets set to "1" (exp 05) or all "2" (exp 06). lr=5e-4, 10 epochs.

**Result:** Both reach 100% per-batch accuracy by epoch 3-4. This proves the GRPO pipeline works correctly -- gradients flow, LoRA updates, the reward signal trains the model. The problem is task difficulty, not infrastructure.

![Trivial sanity check](plots/writeup/grpo_trivial_success.png)

Exp 05 (all-1s) reaches 100% at epoch 4; exp 06 (all-2s) reaches 100% even faster at epoch 2. The asymmetry (06 learns faster) is because the base model already has a slight bias toward answering "1" for IND prompts, so learning "always say 2" requires overcoming that bias.

### Exp 07: High Temperature GRPO (temp=1.5)

**Config:** Same as exp 04 but with sampling temperature=1.5 to force within-group variance.

**Result:** Initially gets GRPO signal (epochs 1-5 show mixed answers and non-zero datums), but collapses into gibberish by epoch 9. All outputs become unparseable tokens.

![Exp 07 collapse](plots/writeup/grpo_07_collapse.png)

The high temperature creates the variance GRPO needs, and accuracy briefly rises above chance in epochs 3-5. But the temperature also amplifies noise -- the model starts producing corrupted outputs (random token sequences) and can never recover. By epoch 9, 100% of outputs are unparseable (`?`), giving 0% accuracy.

**Takeaway:** Temperature is a blunt instrument for creating GRPO signal on this task. The model needs to explore the answer space (1 vs 2), but high temperature instead corrupts the entire output.

## 3. Phase 2: SFT Debug

After GRPO failed on the real task, we switched to supervised fine-tuning (SFT) to isolate the question: *can the model learn these labels at all?*

### Exp 10, 11, 12: Constant-Label Debug

Three experiments on 16 pairwise samples each, lr=1e-4, 10 epochs:

- **Exp 10 (all targets = "1"):** NLL drops from 0.19 to ~0 by epoch 3. Val accuracy = 50% (always predicts "1").
- **Exp 11 (all targets = "2"):** NLL drops from 1.85 to ~0 by epoch 7. Val accuracy = 50% (always predicts "2").
- **Exp 12 (mixed, 8x"1" + 8x"2"):** NLL drops to ~0.34 and plateaus. Val accuracy = 50%.

![SFT debug NLL](plots/writeup/sft_overfit_nll.png)

**Key observation:** The starting NLL reveals a strong prior. "1" starts at NLL=0.19 (model already assigns ~83% probability to token "1"), while "2" starts at NLL=1.85 (only ~16% probability). This 10x asymmetry in starting loss explains why all-1s converges in 2 epochs while all-2s takes 7.

**The mixed plateau:** With mixed labels, NLL plateaus at ~0.34 -- below the chance-level ln(2)=0.69 but far from zero. This is the "bias solution": the model confidently predicts one answer for all samples, getting 50% right with low loss on those correct ones. The model oscillates between all-1s and all-2s predictions across epochs rather than learning per-sample discrimination.

### LR Sweep (mixed 16 samples, rank=32)

To test whether the bias plateau can be broken with more training, we ran 3 learning rates for 30-50 epochs.

![LR sweep](plots/writeup/sft_lr_sweep.png)

| LR | Plateau NLL | Phase Transition | 16/16 Epoch | Notes |
|---|---|---|---|---|
| 1e-4 | ~0.34 | ep 25 | ep 30 | NLL spike to 1.38 then recovery |
| 5e-5 | ~0.34 | ep 40 | ep 50 | NLL spike to 0.68 (smaller overshoot) |
| 1e-5 | ~0.33 | not reached | -- | Still at 14/16 at epoch 50 |

**Phase transition pattern:** All LRs show the same structure:
1. **Rapid drop** (epochs 1-5): NLL falls from ~0.96 to ~0.34
2. **Bias plateau** (epochs 5-25+): NLL stalls at ~0.34, model predicts constant answer
3. **Phase transition**: NLL suddenly drops and train accuracy jumps from 50% to ~100%
4. **Overshoot** (lr=1e-4, 5e-5): NLL spikes briefly after convergence

Higher LR reaches the phase transition sooner but with more instability. lr=1e-5 is too slow to reach it in 50 epochs. The plateau represents a local minimum where the model has learned the marginal distribution (roughly equal 1s and 2s) but not the per-sample mapping.

### Rank Sweep (mixed 16 samples, lr=5e-5, 50 epochs)

![Rank sweep](plots/writeup/sft_rank_sweep.png)

| Rank | Plateau NLL | Phase Transition | 16/16 Epoch | Final NLL |
|---|---|---|---|---|
| 32 | ~0.34 | ep 35-40 | ep 50 | 0.68 (overshoot) |
| 64 | ~0.34 | ep 35-40 | ep 50 | 0.003 (clean) |
| 128 | ~0.34 | ep 35-40 | ep 50 | 0.01 (clean) |

**Rank doesn't matter for learning dynamics.** All three ranks follow nearly identical NLL trajectories through the plateau and phase transition. The only difference is post-convergence stability: rank=32 overshoots to NLL=0.68, while rank=64/128 converge cleanly. This suggests rank=32 is sufficient capacity but slightly less stable at convergence.

## 4. Summary

![Summary bar chart](plots/writeup/summary_accuracy_bar.png)

### Key Takeaways

1. **GRPO fails on the real self-recognition task** because the model is too deterministic at temperature=1.0. With 8 rollouts per prompt, it produces the same (wrong) answer every time, giving GRPO zero gradient signal. Raising temperature to 1.5 creates signal but causes output collapse.

2. **The pipeline itself works.** Trivial GRPO experiments (exp 05, 06) reach 100% accuracy, proving gradients flow correctly through LoRA + Tinker.

3. **SFT can overfit 16 samples, but it's hard.** The model needs 25-50 epochs to break through a "bias plateau" at NLL~0.34 where it predicts a constant answer. This plateau is a local minimum where the model has learned marginal statistics but not per-sample labels.

4. **The base model has a strong prior toward "1"** (NLL=0.19 vs 1.85 for "2"). This asymmetry affects both GRPO and SFT dynamics.

5. **LoRA rank (32/64/128) doesn't affect learning dynamics** -- all ranks show identical plateau behavior and phase transition timing. Rank=64+ is slightly more stable post-convergence.

### What We Learned

- Self-recognition is genuinely hard for the model at baseline (~47% on IND, ~42% on PW). The model can't tell its own outputs from Qwen's.
- GRPO needs within-group variance to produce gradients. For binary classification tasks where the model is confident (even if wrong), GRPO is the wrong algorithm unless combined with curriculum or exploration strategies.
- SFT's bias plateau suggests the pairwise discrimination signals are very weak -- the model learns "roughly half are 1, half are 2" long before learning *which* are which.

### Next Steps

- **SFT warmup + GRPO:** Use SFT to break through the initial bias plateau (get the model above chance), then switch to GRPO for online refinement on the full dataset.
- **Pairwise GRPO:** Use pairwise prompts (showing both responses) which may give the model more signal to discriminate, combined with curriculum scheduling.
- **Scale up SFT:** Run SFT on the full 184-sample pairwise dataset for enough epochs to break through the plateau, then evaluate on held-out val set.
